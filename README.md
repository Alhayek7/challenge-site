# موقع تحدي الـ 30 يومًا | صناع الأثر الرقمي

موقع ثابت (HTML/CSS/JS) + قاعدة بيانات Supabase + نشر مجاني على GitHub Pages. ثلاث صفحات:
- `index.html` — صفحة المشاركين: الترتيب العام وترتيب أعضاء البرنامج، المنصة، السلاسل، التقدم، الدول، الشهادة.
- `register.html` — التسجيل (عضو برنامج بكود / مشارك مفتوح).
- `admin.html` — الإدارة (اسم مستخدم + كلمة مرور).

## 1) إعداد Supabase (10 دقائق)
1. أنشئ مشروعًا مجانيًا على supabase.com.
2. SQL Editor → New query → الصق كامل `supabase/schema.sql` → Run. (يمكن تشغيله مرة ثانية دون ضرر.)
3. Authentication → Users → Add user: البريد `admin@sonna3athr.app` (أو أي اسم@نفس النطاق) وكلمة مرور قوية (10+ أحرف)، وفعّل Auto Confirm.
4. نفّذ في SQL Editor (بعد تعديل الاسم):
   `insert into public.admins(user_id) select id from auth.users where email='admin@sonna3athr.app';`
5. Authentication → Providers → Email: أوقف "Allow new users to sign up" (حتى لا يُنشأ حسابات من الخارج).
6. Project Settings → API: انسخ Project URL و anon public key.

> **تحديث v4:** إن كنت شغّلت schema.sql سابقًا فأعد تشغيله كاملًا مرة أخرى (آمن ولا يحذف بياناتك) ليُنشئ جدول الإعلانات وخانة «نشر الفائزين».

## 2) ضبط الموقع
افتح `assets/js/config.js` وعدّل ما عليه علامة ✏️:
| ما تغيّره | أين |
|---|---|
| SUPABASE_URL / SUPABASE_ANON_KEY | config.js (الـ anon key آمن للنشر العلني بفضل RLS) |
| ADMIN_EMAIL_DOMAIN | يجب أن يطابق نطاق بريد الأدمن. المستخدم يكتب `admin` فقط |
| رابط الإنستغرام والواتساب والمجموعة | config.js |
| ORG_SHORT / ORG_ABOUT | اسم المؤسسة المختصر ونبذتها (تظهر في الهيرو وقسم الرعاية) |
| شعار المرقاة | استبدل assets/marqat-white.png بنسخة أعلى جودة (خلفية شفافة، أبيض) إن وُجدت؛ الشعار الحالي أُخذ من صورة صغيرة |
| SITE_URL | رابط الموقع بعد النشر |
| النصوص، الأسئلة الشائعة، رسالة التذكير | config.js |
| CERT_MIN_PERCENT، CERT_SIGNER | شرط الشهادة (80% افتراضيًا) والتوقيع |
| المنطقة الزمنية | `TIMEZONE` في config.js **و** `Asia/Gaza` في schema.sql (يجب أن يتطابقا) |
| تاريخ البداية، المكافأة، الفائزين | لوحة الإدارة ← الإعدادات (دون تعديل كود) |
| الألوان | أعلى assets/css/style.css |

## 3) النشر على GitHub Pages
1. أنشئ مستودعًا جديدًا وارفع **محتويات** المجلد (يجب أن يكون index.html في الجذر، وملف `.nojekyll` موجود).
2. Settings → Pages → Branch: main / root → Save.
3. بعد دقيقة يظهر الرابط. ضعه في `SITE_URL` وفي `og:image` داخل index.html كرابط مطلق (مثال `https://user.github.io/repo/assets/og-image.png`) ليظهر تصميم المعاينة عند المشاركة.

## 4) أول استخدام
1. ادخل `admin.html` ← تبويب الإعدادات: اضبط تاريخ البداية والجوائز.
2. تبويب «أكواد العضوية»: ولّد الأكواد (إما عدد، أو الصق أسماء الأعضاء لكل واحد كود)، ثم «نسخ المتاحة» ووزّعها على الأعضاء.
3. العضو يسجل في register.html ويختار «عضو في البرنامج» ويكتب كوده. الكود يُستخدم مرة واحدة والسيرفر هو من يتحقق (الأكواد مخفية عن الزوار ومحمية من التخمين: 10 محاولات خاطئة كل 10 دقائق).
4. المشارك المفتوح يسجّل بدون كود ويظهر في الترتيب العام فقط؛ أما الجوائز فتُحسب من «المنافسة على الجوائز» (أعضاء البرنامج).
5. الطلبات الجديدة تصل لتبويب «الطلبات» ← اعتمد (أو اعتماد الكل).
6. يوميًا: تبويب «اليوم» ← من لم ينشر، رسالة تذكير جاهزة للواتساب. وفي «جدول المتابعة» اضغط الخلية لتسجيل اليوم.
7. المشاركون يرسلون رابط ريلزهم من الصفحة الرئيسية، فتظهر خلية صفراء تعتمدها أنت.

## صلاحيات الأدمن (كلها من admin.html)
جدول المتابعة (تسجيل/اعتماد/إلغاء أي يوم) · الطلبات (قبول/رفض/قبول الكل) · المشاركون (إضافة/تعديل/حذف/تغيير النوع والدولة) · أكواد العضوية (توليد/ملاحظة/تحرير/حذف/تصدير) · الفائزون (حساب تلقائي + نشر احتفالي على الموقع + نسخ نص التهنئة) · الإعلانات (شريط الأخبار المتحرك) · الإعدادات (التاريخ، الجوائز، فتح/إغلاق التسجيل) · نسخة احتياطية · تغيير كلمة المرور · منطقة الخطر (حذف المرفوضين، تصفير الإنجازات).

## ملاحظات وقرارات تصميمية
- الترتيب: عدد الأيام المنجزة ← السلسلة الحالية ← أطول سلسلة ← الاسم.
- القواعد مفروضة في قاعدة البيانات لا في المتصفح: لا يمكن إرسال يوم مستقبلي ولا أقدم من 6 أيام، مع مهلة 3 أيام بعد النهاية، وكل إرسال ذاتي يبدأ «قيد الاعتماد».
- إذا حذفت مشاركًا يتحرر كوده تلقائيًا.
- الحد الأقصى للمشاركين 300 (غيّره في schema.sql).
- الصور: تُضغط في المتصفح إلى 480px وتُرفع لـ Storage (حد 1MB).
- الشهادة تُرسم في المتصفح كصورة PNG بلا خادم.
- الخصوصية: لا تُجمع أرقام هواتف ولا بريد للمشاركين؛ الظاهر علنًا: الاسم، الصورة، حساب إنستغرام، التخصص، الدولة، المدينة.
- لا تعرض حقل الكود ولا ملف النسخة الاحتياطية لأحد (فيه الأكواد).

## جولة جديدة
من SQL Editor: `truncate public.submissions;` ثم احذف المشاركين القدامى أو أبقِهم، وعدّل تاريخ البداية من الإعدادات. للأكواد: ولّد جديدة أو حرّر المستخدمة من تبويب الأكواد.

## مشاكل شائعة
- «وضع المعاينة» يظهر: لم تُعدَّل بيانات Supabase في config.js.
- لا يمكنني الدخول: تأكد من Auto Confirm ومن إدراج المستخدم في admins ومن تطابق النطاق.
- الصور لا ترفع: تأكد أن schema.sql شُغّل كاملًا (إنشاء bucket اسمه avatars).
